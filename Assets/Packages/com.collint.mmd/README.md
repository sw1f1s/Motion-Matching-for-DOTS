# Motion Matching for DOTS

MMD — плагин анимации для Unity Entities: Motion Matching, воспроизведение скелетной анимации, root motion и GPU-деформация через Entities Graphics. Идентификатор: `com.collint.mmd`, namespace: `ColInt.MMD`.

Текущая версия — **0.3.1**. См. [Changelog](CHANGELOG.md); базы форматов ниже 7 нужно перепечь. Обновление с 0.3.0 не требует повторного запекания базы.

## Установка

Unity 6000.3+ и URP. Этот пакет содержит только `Runtime` и `Editor`; сцены, управление персонажем, анимации и тесты поставляются отдельно в `com.collint.mmd.samples`.

Для установки только ядра в Package Manager выберите **Install package from tarball** и укажите `com.collint.mmd-0.3.1.tgz`. Git LFS для архива не нужен. В проекте разработки архив создаётся командой `python3 Tools/package_release.py --package core`.

После публикации изменений можно установить ядро через **Install package from Git URL**:

```text
https://github.com/sw1f1s/Motion-Matching-for-DOTS.git?path=Assets/Packages/com.collint.mmd#main
```

Entities 1.4.3, Entities Graphics 1.4.3, Unity Physics 1.4.3, Collections, Burst, Mathematics, Newtonsoft JSON и URP указаны в `package.json` и разрешаются UPM. Input System, Animation и Terrain Physics объявлены в пакете Samples.

Для примеров сначала установите это ядро, затем `com.collint.mmd.samples-0.3.1.tgz`. Общий ZIP `mmd-with-samples-0.3.1.zip` содержит оба архива. Подробности — в [инструкции Samples](../com.collint.mmd.samples/README.md). Git-установка из общего репозитория может скачивать и содержимое Samples; отдельный архив позволяет скачать только ядро. Старый тег `v0.1.0` содержит прежний объединённый пакет.

Код MMD распространяется под MIT. Сторонние анимации и модели принадлежат пакету Samples и сохраняют исходные условия; см. его [Third Party Notices](../com.collint.mmd.samples/Third%20Party%20Notices.md).

## Как работает

При запекании клипы превращаются в `.bytes` базу: позы костей, движение корня, признаки для поиска и именованные группы. Постоянные каналы сохраняются одним значением, вращения костей упаковываются с ограничением погрешности.

Каждый фиксированный ECS-такт игровая система задаёт желаемую траекторию и ограничения групп. MMD сравнивает будущий путь, направление, скорость и положение/скорость стоп с кадрами базы, выбирает подходящий фрагмент, воспроизводит позу и сглаживает переход. Root motion применяется в симуляции; рендер читает готовую позу и деформирует меш на GPU.

Анимационные и render-компоненты находятся на одной основной сущности в одном мире. Unity создаёт технические сущности мешей при baking. Управление, камера, игровые состояния и создание мира принадлежат проекту; GPU-рендер читает результат симуляции.

## Подготовка анимаций

1. Импортируйте клипы и настройте совместимые Rig/Avatar. Зацикливание задаётся через **Loop Time** у анимации.
2. Создайте `MotionBakeConfiguration`: укажите целевой rig, пути корня/стоп, группы и клипы. Для обычного поиска выберите **Motion Matching**, для запуска отдельным запросом — **Action**.
3. Нажмите **Bake Database** в инспекторе. Укажите путь к `.bytes` внутри `Assets`. В проекте разработки можно запекать прямо в Sample: `Assets/Packages/com.collint.mmd.samples/Databases/Locomotion.bytes`. При установке из Git сохраняйте собственные базы и конфигурации в `Assets`.

Группы задаются именами; идентификаторы групп и Action ID генерируются автоматически. Количество групп не ограничено размером битовой маски. Клип может входить в несколько групп; их принадлежность хранится один раз на клип. База запекается под целевой скелет; персонажи с этим скелетом могут совместно использовать один BlobAsset. Ретаргетинг Humanoid выполняется при запекании. В **Bake Settings → Normalization Groups** можно закрепить группы для расчёта весов поиска; пустой список использует все клипы.

## Слои и маски анимации

Слои применяются после playback и инерциализации локомоушена, перед расчётом матриц. Каждый слой заменяет выбранные локальные каналы позы с весом `Weight × Bone Weight`. Порядок списка задаёт приоритет: последний слой применяется последним. Root motion всегда остаётся от базового playback. Маски с изменённым root/тазом могут менять визуальную позу, поэтому для оружия оставляйте эти кости с нулевым весом.

1. В bake-конфигурации добавьте группу с оружейными клипами и **Playback → Layer Only**, затем запеките базу. Эти клипы могут зацикливаться и не участвуют в поиске или нормализации его весов. Один клип может входить в несколько Layer Only групп; смешивать разные режимы групп для одного клипа нельзя.
2. Создайте **Create → MMD → Animation Mask**. Укажите тот же **Target Rig**, что при bake, и нажмите **Sync Rig**. Новые кости получают вес 0, существующие сохраняют вес по полному пути. Кнопки **Right Arm**, **Left Arm**, **Upper Body** создают пресеты для Humanoid. Для Generic используйте дерево костей.
3. Слайдер задаёт вес кости от 0 до 1. **Apply weight to children** меняет всю ветку — удобно включить плечо, предплечье, кисть и пальцы. Кости отображаются в стандартном дереве Unity с колонками Bone, Weight и Value. Ширину колонок можно менять перетаскиванием границ заголовков; для числового веса зарезервировано отдельное место. Активные кости выделяются цветом, под деревом показано количество затронутых костей. Поиск фильтрует дерево по имени/пути; **Expand/Collapse** раскрывают или сворачивают ветки, **Clear** обнуляет маску. Все изменения поддерживают Undo. Маска должна точно соответствовать скелету базы.
4. Создайте **Create → MMD → Animation Layers**, укажите **Baked Database** и добавьте слой. Выберите маску и **Source**: **Clip** использует выбранный клип внутри группы, **Group** подбирает кадры среди всех клипов группы через Motion Matching по запросу движения персонажа. В режиме Group выбор одного клипа и начального Time скрыт; при переключении в Group скорость автоматически становится 1, если раньше удерживалась неподвижная поза. Имена клипов берутся из необязательного bake-каталога; без него отображается индекс клипа. **Edit Mask** открывает выбранную маску. Кнопки ↑/↓ меняют приоритет.
5. **Time** задаёт начальное время в секундах; **Speed = 0** удерживает эту позу, **Speed = 1** проигрывает клип. Loop берётся из базы, обычный клип останавливается на последнем кадре. **Weight** — целевой вес, **Fade Duration** — время перехода по полному диапазону 0–1. Для руки начните с **Channels → Rotation**, чтобы сохранить длины костей; Position и Scale можно включить отдельно.
6. В Sample Character Configuration назначьте полученный asset в **Animation Layers**. Он должен ссылаться на ту же `.bytes` базу, что и персонаж. Несколько персонажей используют общие настройки, но независимые время, вес и ECS-буферы слоёв.

Для Group в **Motion Matching Settings** задаются интервал поиска, штраф переключения, ограничения по времени клипа и **Transition Duration** — длительность сглаживания смены кадров внутри слоя. Слой использует ту же траекторию и признаки движения, что и персонаж, но ограничивает поиск выбранной группой, включая Layer Only. У группы независимы выбор клипа, время, история переходов и вес; базовый playback и его root motion не переключаются. Для Group требуется положительная Speed и буфер `MmdSearchQueryElement` на персонаже.

В **Base Groups** выберите группы базовой анимации через стандартное поле флагов Unity. **Everything** отмечает все группы поля, **Nothing** очищает выбор и выключает слой. Отдельные группы включаются галочками в меню. При количестве групп больше 64 выбор разбивается на поля по 64 группы; каждое поле меняет только свой блок. Достаточно совпадения хотя бы с одной группой текущего базового клипа. Новые группы остаются выключенными, пока их не отметят. Вход и выход используют **Fade Duration**, не меняя заданный Weight. Группа источника слоя и группы его включения настраиваются отдельно. Выбор в asset хранит имена, чтобы перестановка групп при bake не меняла смысл настройки; при создании персонажа имена преобразуются в битовую маску.

Настройки конкретного клипа хранят имя группы и порядковый номер внутри неё. После перестановки клипов в bake-группе проверьте выбор слоя. Переключение веса допускает прерывание перехода, пауза и Disabled останавливают время и вес. Удаление персонажа и мира освобождает буферы штатным ECS lifecycle. Слои не добавляют событий Action и не меняют историю инерциализации базового слоя.

Для собственного ECS-персонажа сначала создайте общий набор слоёв. `Build` проверяет настройки и создаёт BlobAsset с описаниями, масками групп и только костями с ненулевым весом:

```csharp
var layerSet = MmdAnimationLayerBuilder.Build(database, configuration.Layers);
MmdAnimationLayers.Add(entityManager, character, layerSet);
// Тот же layerSet можно подключить к другим персонажам с той же database.
var requests = entityManager.GetBuffer<MmdAnimationLayerRequest>(character);
MmdAnimationLayers.SetWeight(requests, 0, 1f, 0.2f);
MmdAnimationLayers.Play(requests, 0, clipIndex, 0f, 1f);
MmdAnimationLayers.SetGroup(requests, 0, groupId, 1.5f);
```

Хост владеет `MmdAnimationLayerSet`: сохраняйте его на всё время жизни персонажей, затем завершите jobs/уничтожьте мир, вызовите `layerSet.Dispose()` и только после этого освободите базу. Sample делает это автоматически и разделяет один набор между персонажами с общей конфигурацией.

`MmdAnimationLayersDefinitionReference` ссылается на общее неизменяемое описание. `MmdAnimationLayerControl` хранит источник, скорость и целевой вес персонажа; изменяйте их через запросы `MmdAnimationLayerRequest`. `MmdAnimationLayer` хранит текущий клип, время, вес и состояние поиска. `MmdAnimationLayerPose` содержит разреженную историю только затронутых костей. Запросы обрабатываются перед поиском слоя; `Play` и `SetGroup` сами готовят переход. Неверный запрос отклоняется с `MmdFaultCode.InvalidLayerRequest`, сохраняя текущее проигрывание.

`MmdLocalPose` — базовая поза для поиска движения, контактов и root motion. Слои записывают отдельный `MmdComposedPose`, который использует расчёт матриц рендера. Слой с нулевым текущим и эффективным целевым весом не ищет кадры и не обновляет время/историю. При включении поиск запускается сразу; при затухании слой продолжает работать до нулевого веса. Положительная скорость Group, включая значения больше 1, одинаково применяется к поиску и проигрыванию.

В базе `MotionPlaybackMode` явно задаёт `MotionMatching`, `Action` или `LayerOnly`. `ActionId` положителен только для Action; остальные режимы используют 0. Формат базы — **7**: старые базы нужно перепечь. Sample-база обновлена вместе с кодом. Слои поддерживают Override выбранных каналов; Additive и IK пока не входят в пакет.

## Подключение к своему миру

Установите системы в существующие группы своего ECS-мира:

```csharp
MmdSystemInstaller.Install(world, fixedTickGroup);
MmdSystemInstaller.InstallInitialization(world, initializationGroup);
MmdPhysicsInstaller.Install(world, fixedTickGroup);
MmdGraphicsInstaller.Install(world, presentationGroup);
```

Installers находятся в `ColInt.MMD.Lifecycle.Helpers`, `.Physics.Helpers` и `.Graphics.Helpers`. Мир должен уже содержать стандартные системы загрузки сцен/префабов, трансформов, физики и Entities Graphics. Проект управляет PlayerLoop, фиксированным шагом и одним singleton `MmdWorldState`, в который передаёт паузу.

Загрузите базу через `MotionDatabaseCodec.Load(textAsset.GetData<byte>())`. На персонаже создайте обязательные данные из таблицы ниже; `MmdPlayback` начните со `Speed = 1f`, `MatchedFrame = -1`. Буфер запроса должен иметь размер `database.Value.FeatureCount`; заполните его до поиска. Скелет и начальную позу задайте по базе. Полный пример инициализации — [MmdSampleCharacterFactory](../com.collint.mmd.samples/Scripts/Character/Helpers/MmdSampleCharacterFactory.cs).

Загруженный runtime BlobAsset принадлежит проекту: разделяйте его между персонажами и освобождайте после завершения jobs и удаления потребителей. Sample освобождает базы после своего мира.

| --- | --- |
| `Lifecycle / MmdWorldState` | Singleton мира; `IsPaused` останавливает анимационную симуляцию. |
| `Database / MmdDatabase` | Ссылка `Value` на общую базу персонажа. |
| `MotionMatching / MmdSearchSettings` | Частота поиска, штраф переключения и ограничения переходов. ## Управление поиском и действиями

`LocomotionSchema` формирует запрос из 27 признаков: путь на 0.2/0.4/0.6 секунды, скорость корня и состояние стоп. Используйте `WriteTrajectory` для простого прогноза и `WritePose` для позы; вариант с `MmdLocalPose` и буфером `MmdPoseFeatureHistory` учитывает отображаемый переход. Свой прогноз движения можно записывать напрямую. Для физического ограничения обновляйте также `MmdTrajectoryPoint` и `MmdSearchQuerySpace` перед `MmdTrajectoryConstraintGroup`.

Разрешайте группы по имени из текущей базы, например:

```csharp
var groups = entityManager.GetBuffer<MmdMotionGroup>(character);
int run = MotionDatabaseGroups.GetId(
    ref database.Value, new FixedString64Bytes("Run"));
MmdMotionGroups.Set(groups, MmdMotionGroupUsage.Required, run);
// Для пересечения групп вызовите Add с Required для другого ID.
```

Добавьте буфер `MmdMotionGroup` на сущность вместе с компонентами поиска. `Set` меняет только выбранное назначение, сохраняя остальные; `Add` и `Remove` изменяют отдельную группу. Не сохраняйте сгенерированные ID между запеканиями. Формат базы — 7; после обновления пакета свои базы нужно перепечь. `BitMask` — не владеющее памятью представление над `NativeArray<ulong>` для `And`, `Or`, `Xor`, `AndNot`, `Not`, `Intersects` и `ContainsAll`. Операции меняют переданное хранилище без выделений памяти; его размер и освобождение задаёт владелец. Нумерация битов в `BitMask` начинается с 0, ID групп — с 1. Готовую маску можно передать в `MmdMotionGroups.Set(groups, usage, mask)`, `Add(groups, mask, usage)` (OR) и `Remove(groups, mask, usage)` (AND NOT).

Для немедленного поиска после изменения намерения установите `MmdPlayback.SearchCountdown = 0f`; для прерывания удержания перехода — также `TransitionElapsed = settings.MinimumTransitionTime`.

Для отдельного действия заполните `MmdActionRequest.ActionId` через `MotionDatabaseGroups.GetActionId`, задайте `PreferredClip = -1` и увеличьте `Revision`. Читайте `MmdActionState.Completed` / `Rejected`. Возврат к Motion Matching выполняется новым запросом с `ActionId = 0` и новой revision; игровые состояния переключает проект.

GPU-префаб должен иметь `MmdGpuCharacterAuthoring` на корне и `MmdGpuSkinAuthoring` на SkinnedMeshRenderer, тот же скелет, что у базы, и материал `ColInt/MMD/Deformed Lit`. Задайте `MmdGpuCharacterRender.Prefab` до инициализации. Маркер `MmdGpuCharacterRenderInitialized` и ресурсы компонента обслуживаются системами; очистка выполняется при удалении владельца и закрытии мира.

Модель связывает каждую свою сетку с костями базы по путям и иерархии. Порядок костей, названия и число объектов сеток могут различаться: индексы скиннинга переназначаются при подключении экземпляра. Дополнительные узлы в базе не мешают привязке. Одежду и аксессуары со скиннингом на общие кости можно добавлять отдельными сетками с `MmdGpuSkinAuthoring`. Все используемые ими кости и их предки должны присутствовать в базе; отсутствие кости, другая иерархия или неоднозначные пути дают ошибку совместимости. Это привязка общего скелета, а не ретаргетинг скелетов с другими именами, пропорциями или позой покоя. Базу из-за переименования сеток перепекать не требуется.

## Примеры и отладка

- [MMDSampleEnvironment](../com.collint.mmd.samples/Scenes/MMDSampleEnvironment.unity) — интеграция с управлением персонажем, локомоцией, приседом, спринтом, слайдом, прыжком, падением, приземлением и Traversal. Эта игровая логика находится в `Scripts/Character/Movement` пакета Samples.
- [MMDSampleBenchmark](../com.collint.mmd.samples/Scenes/MMDSampleBenchmark.unity) — множество персонажей с одной базой и GPU-префабом. Количество, seed и область движения задаются на **Benchmark Characters**; каждый персонаж получает свой `MmdSampleInput` от системы выбора цели.
- `Locomotion.ReversalGroup` в Sample-конфигурации задаёт группу разворотов с упором ноги. При резкой смене направления бега/спринта поиск выбирает из неё и текущей группы скорости; после разворота возвращается к циклу. Группа `Reversal` в Sample содержит левые и правые клипы на 180°.
- [MmdSampleWorld](../com.collint.mmd.samples/Scripts/Lifecycle/MmdSampleWorld.cs) и [MmdSampleCharacterFactory](../com.collint.mmd.samples/Scripts/Character/Helpers/MmdSampleCharacterFactory.cs) — примеры подключения систем, создания сущностей и освобождения ресурсов.

Ввод Sample хранится на персонаже в `MmdSampleInput`: направление движения и камеры, режим ходьба/бег, удерживаемый спринт, переключатель присяда и одноразовые нажатия. Маркер `MmdSamplePlayerInput` подключает сущность к `MmdSamplePlayerInputSystem`; его необязательная ссылка `Camera` задаёт направление движения относительно камеры. `InputSystemActions.inputactions` находится в `Configurations` пакета Samples, генерируемый класс — в `Scripts/Character/Input/Data` пакета Samples. Биндинги меняются в Unity Input Actions.

Система считывает действия каждый кадр и сохраняет нажатия до шага симуляции; `MmdSampleInputCleanupSystem` очищает их после обработки состояний. Боты записывают тот же компонент своей системой без маркера игрока. `MmdSampleSimulationDriver` только вызывает шаги мира; у `MmdSampleWorld` нет глобального ввода или `SetInput`. Например: `entityManager.SetComponentData(character, new MmdSampleInput { Movement = direction, Run = true });`.

Управление Sample: **WASD** — движение относительно камеры, **X** — переключение ходьба/бег (по умолчанию бег), **Shift** — спринт и выход из присяда, **Ctrl** — переключение присяда. Нажатие Ctrl во время спринта запускает слайд: на ровной поверхности он тормозит, на спуске сохраняет скорость и ускоряется под действием уклона. Удерживаемый Shift имеет приоритет над присядом: после слайда персонаж встаёт и при наличии ввода продолжает спринт. Для присяда после отпускания Shift нужно снова нажать Ctrl. Скорости и параметры слайда задаются в `MmdSampleCharacterConfiguration`. **Space** — прыжок или Traversal.

В своём проекте используйте собственный мир и игровые системы. Для переноса Sample-геометрии в другой проект выполните **Bake World Physics** на компоненте `MmdSampleWorldPhysicsGeometry`: кеш зависит от версии Unity и физических пакетов.

**Window → Motion Matching for DOTS → Debugger** показывает сущности, текущие клипы, группы и прогресс. В развёрнутой карточке доступны переходы и история последних пяти клипов; **Show in Entities Hierarchy** выбирает сущность для инспекции. Траектория отображается через `MmdTrajectoryDebug`.

Тесты поставляются в отдельном пакете Samples, в `Tests/EditMode` и `Tests/PlayMode`. При UPM-установке добавьте `"testables": ["com.collint.mmd.samples"]` в `Packages/manifest.json` и установите Unity Test Framework; затем запускайте тесты через Unity Test Runner. Производительность измеряйте в Profiler при одинаковых количестве персонажей, seed и частоте симуляции.
